# Library external module identity

Mechanism inventory before edits: workspace libraries capture `BuildUnitOptions.externals` and hash it in `effectiveBuildVersion` (`builder.ts:2293–2345`); npm and platform libraries hash through `externalLibraryBuildKey` (`builder.ts:6009–6029`) and then compile through `doNpmBuild`/`doPlatformBuild`. Workspace compilation uses `buildLibraryBundle`; all three producers must canonicalize both cache identity and captured compiler input. `index.ts:getBuildInternal` and `buildService.ts:getBuild` route both panel and native-worker requests to these producers. Base `packages/eval/src/sandbox.ts:480` derives the array from module-map insertion order; SDK `clients/evalImportLoader.ts:116` forwards it. Their input order is not a semantic distinction: all external predicates are unions/set membership.

Workspace cache identity previously distinguished order; external-library identity sorted but retained redundant duplicates. This causes avoidable separate cold builds and prevents equivalent requests from sharing flights. The common default is a sorted unique snapshot, retaining exact distinct aliases (`util` and `node:util` remain different). `VIBESTUDIO_CANONICAL_LIBRARY_EXTERNALS=0` restores the previous diagnostic behavior. Tests exercise the public workspace key and npm/platform cache lookup boundaries.

This defect was found while investigating a doctor library whose native checkpoint waited 148 seconds. Its original cause remains open: the artifact was published 34 seconds after Eval cancellation, while isolated warm-dependency compilation took 6.8 seconds and cold immutable projection 0.68 seconds. Neither a payload limit nor this identity defect is established as that specific run's cause. No timeout, readiness skip or ambient automation behavior is changed.

Validation: ledger unit `library-external-identity-tests-20261123b` passed all four key/lookup tests (294 MiB peak). The unrelated panel artifact fingerprint is fixed in these tests; production key and public lookup implementations execute unchanged. The initial test setup omitted the required artifact root and failed before assertions; its log is retained.
