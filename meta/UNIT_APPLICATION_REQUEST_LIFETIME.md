# Explicit unit application requests

The existing UnitHost application map retained the latest promise after settlement. That is useful for truthful late `whenApplied` observers, but ClientRegistry awaited that rejection before reaching its existing native recovery path. A failed background declaration could therefore block later explicit launches of unchanged, already authorized source.

The same application record now distinguishes pending work from its settled result and records the exact canonical candidate identity. `ensureApplied(node,decl)` is an authorized explicit request: it joins an identical pending application, preserves its original failure, or starts one new owned attempt after a previous attempt settled. A different exact declaration waits for the previous owner to join before starting. Existing user-approved active identities remain reusable; no new approval or grant is manufactured. Missing authority admission still overrides preapproval.

Client launch and UnitHost.whenReviewed use this canonical request path. Passive whenApplied keeps the original result observable. Explicit work is registered before resource publication and joined by whenSettled; late completion updates only its own record. No timer, retry loop, automatic retry after a current failure, source mutation, or failure-history deletion is added.

Inventory: UnitHost.applications/prepareTrustedApplications/whenApplied/whenReviewed/whenSettled are the shared producer/join mechanism; ClientRegistry.ensureActivated was its other direct whenApplied consumer. Existing applyTrusted/applyRuntimeDeclaration, candidate trust, admission and build freshness checks remain authoritative across unit kinds. Compiler BuildStore/UnitValidationStore and model/credential routes are separate mechanisms. The actual0066 terminal capacity failure is not attributed to this readiness issue.

This successor also preserves known typed BuildRequestError failures as schema/input diagnostics rather than classifying them as unknown operational failures. Such deterministic caller defects retain their correct category; native operational causes remain infrastructure diagnostics.
