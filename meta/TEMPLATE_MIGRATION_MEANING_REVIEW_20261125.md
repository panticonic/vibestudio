# Native migration findings require meaning review

The actual Source35 read-only migration capture correctly rejected an unrelated group's receipt as evidence of current adoption, but the native validator rejected its incidental `draft-only` status instead of the expected label. The user requested an answer grounded in owned migration records, not a particular status enum.

The shared observed-content admission mechanism now includes template migration. Its existing registration path derives mandatory review from this domain mapping; its exporter binds the original goal, actual native journal/source observations/read IDs/current protected main/candidate preparation, retained handoff bytes and any required actual returned value. No authored answer vocabulary or expected enum enters admission. The same binder rejects altered observations, candidate preparation, return values, review flags and retained receipt bytes. Native ownership, source/current-state, authority, protected main and artifact checks remain in the template validator. Existing domains and runtime/model routing do not change.

Inventory: `scripts/lib/observed-content-admission.mjs` owns supported evidence fields, review registration and bound review input. `scripts/export-live-workflow-teacher.mjs` consumes `observedContentNeedsReview` when registering every discovered workflow and `observedContentReviewInput` when exporting native proofs. `scripts/collect-live-workflow-teacher.mjs` uses those registered review flags before execution and calls the existing reviewer after native assessment. The existing reviewer consumes the same goal-bound input; no second review protocol or generated declaration is needed. Corresponding native template source lives in `skills/system-testing/open-goal-template-migration-managed.ts` and its cases; that companion source is required for this mapping.
