# Schema admission priority

Startup requests speculative builds in startupWorkerPreparation.ts, but schemaProbeEvidence.ts previously created an interactive owner unconditionally. workerdManager.ts shared only a Promise, preventing later interactive entity demand from promoting queued startup admission. BuildFlight/BuildPriorityOwner in buildV2/builderLifetime.ts already implement the required strongest-caller promotion. Schema identity, receipt validation, native import/schema/class validation, and authority are unchanged.

The startup executable callback now carries speculative priority independently of executable retention; VIBESTUDIO_STARTUP_INTERACTIVE_SCHEMA_ADMISSION=1 restores interactive schema priority for diagnosis. WorkerdManager preserves one exact-executable admission flight and promotes that owner on joining demand. The cache coordinator receives the same owner. Shutdown joins actual flight promises. Direct schema probes and all non-startup demand default to interactive.

Consumers inventoried: startupWorkerPreparation.ts and index.ts callback; WorkerdManager prepare/restore/entity/direct probe and shutdown; services/schemaProbeEvidence.ts; SharedBuildCoordinator admission and BuildFlight promotion. Browser/Core model engines do not own Host schema admission or this Node-only cache coordinator. Modern Host RuntimeManager has the analogous mechanism and is corrected in a separate main-based successor; no legacy manager will be restored there. This is a scheduling correction, not a measured startup RSS or latency claim.

Validation: production selected Host source passed 50 focused controls (including existing schema/cache/lifetime controls), then the simplified spy-only owner forwarding assertion passed independently. Modern main RuntimeManager counterpart passed 12 focused controls. Initial promotion fixtures accidentally used different immutable source selectors (production ctx:fresh vs fresh, modern main vs ctx:fresh); those failed as independent probes should, and corrected exact-selector controls passed. Modern native CellD executable is still unavailable; no real CellD execution claim.
