# Join speculative validation without retaining unused named executables

Speculative startup builds every discovered worker, then performed full executable preparation. That preparation published a persistent warm image before validation returned and retained a named WorkerLoader unit without an entity. A failed replacement could therefore keep an unvalidated prepared owner. Named WorkerLoader units have no individual unload operation.

Startup preparation now requests an operation lifetime. It still admits the exact native schema and actually imports/validates the executable class; its private image and authority live until the native validation fetch settles. Its loader entry is anonymous and is not reported as a persistent named isolate. Native dispatch and explicitly requested shared warm preparation retain named reuse. `VIBESTUDIO_STARTUP_RETAIN_WORKER_EXECUTABLES=1` opts startup back into shared warm ownership. Shared prepared publication happens only after successful validation. A failed or stale operation deletes only its own image and preserves an existing/newer valid shared owner. Shutdown cancellation is passed into, and joined through, the actual validation fetch.

Inventory: startupWorkerPreparation.ts/index.ts create the speculative operation; workerdManager.ts owns preparation/image publication, schema admission and code/egress lifetime; workerdPrograms/universalDo.ts owns anonymous/shared loader selection; gateway.ts forwards the private lifetime. Both real Workerd test gateways forward the same field. SchemaProbeEvidence and its exact installed/shared cache remain unchanged. Schema probes already use anonymous loading and retire their facet/storage; no probe leak is established. Generation engines do not own this Host WorkerLoader mechanism; all Node workspace hosts use these same preparation/gateway producers.

Validation: 16 focused controls passed in 8.37s/423MiB: six startup controls including opt-out/abort joining, seven manager controls including failed replacement, stale older completion, concurrent operation/shared preparation and cancellation, one private gateway control and two REAL Workerd controls. The real controls compile the changed canonical typed workerd programs with buildWorkerdPrograms({write:false}) from this worktree and prove: operation validation constructs no user object; demand fetches a fresh named unit; a second object reuses that named unit; explicit shared warm preparation still reuses it immediately. They use no old compiled donor, no model or provider network call.
