# Native custody for pending model exchanges

Natlang provider ABI 3 adds the private `retainCaptureEvidence` host callback and optional provider `pendingCaptureEvidence` recovery read. The complete provider runCell lifecycle executes inside its actual Eval execution context, including final persistence. The callback accepts only schema `natlang.pending-model-exchanges/1` with its exact actual run and owner. It stores original serialized JSON in transactional, surrogate-safe 64K character SQLite chunks, with a SHA-256, byte/character counts, actual provider bundle/execution identity, owner/context/run and kernel incarnation.

This is preservation of original evidence; it never marks a trajectory successful or admits a training target.

Host-only `eval-engine.readPendingCaptureEvidence` returns at most eight rows per page. `runtimeEntityCleanup` invokes one common archival path for finite eval disposal, individual retirement, context destruction and reaper retries. It recognizes the actual builtin EvalDO source/class and verifies native ownership, context, row/chunk sequence, exact digest and lengths before publication. The payload and native/runtime manifest are atomically written under `state/capture-evidence/natlang/<sha256(entityId)>/<payloadSha>.json` and `.manifest.json`, with private file permissions. The existing atomic writer syncs the manifest and directory after the streamed payload is synced.

Archival failure propagates while independent process/resource cleanup continues. The entity remains cleanupComplete=false for the existing reaper. WorkerdManager.retireDOEntity deliberately preserves native durable SQLite storage (workerdManager.ts1779 onward), so failed archival retains its original rows; Eval reset also preserves the native state table. No fabricated permanent blob-retention namespace or memory-only fallback is used.
