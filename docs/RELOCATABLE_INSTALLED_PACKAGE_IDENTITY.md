# Installed dependency identity across host relocation

The installed package fold in `src/server/buildV2/effectiveVersion.ts` hashes literal `readlink` targets for package roots and then skips their dependency realms. These links are installation coordinates: private first-party overlays on two hosts can contain identical implementations and resolution graphs at different absolute paths. Conversely, identical manifests can point to different source implementations or dependency resolutions. Removing link strings without replacing their actual content/graph identity would be unsound.

Inventory before implementation:

- `effectiveVersion.ts`: root dependency files and host-local implementation trees feed `computeRootDependencyFingerprint`; installed realms currently combine manifest hashes, nesting and raw link spelling. This is the producer requiring correction. Physical paths remain diagnostics in `RootDependencyFingerprintInfo`, not folded values.
- `effectiveVersion.ts` capture/validate/compose functions seal and recombine the same host dependency fold with workspace inputs. `computeBuildKey`, prepared workspace release validation and runtime builders consume that shared value; none may substitute an old receipt or waive mismatches.
- `preparedDependencyResolution.ts`, `typecheckDependencyGraph.ts`, `externalDeps.ts` and `builder.dependencyEnvironment` resolve real package locations. Their physical coordinates are resource lookup, lifetime-local maps or authority checks, not portable key material; keep those checks.
- `scripts/host-build-fingerprint.mjs` and `scripts/infrastructure-package-cache.mjs` hash authored source trees, including literal source symlink objects. Those links are source inputs rather than installed package aliases: preserve their spelling. `immutableTreeMaterializer.ts` rejects absolute or escaping links in transported source trees. Reinterpreting arbitrary authored links as installation aliases would remove a real input.
- `scripts/host-build-generations.mjs` records relative node_modules links in published generations. Its location/ownership validation remains; it must not relabel artifact identities.
- `packages/shared/src/runtimePaths.ts` uses physical roots for installed executable discovery and process-local memoization. Platform/architecture identity belongs to executable selection, not this platform-neutral library fold.
- Model serving engines (managed llama, wllama, Python and SGLang) do not produce this Vibe installed-package fingerprint. They consume model/engine artifacts with their own identities; this change does not alter model identity or inference routing.

The new installed fold must identify actual resolved package nodes, manifest bytes, declared local implementation bytes and actual dependency edges, using physical locations only to discover/intern nodes and terminate cycles. Its serialized graph must contain no host absolute address. Platform-gated package nodes remain excluded, while wrapper manifests still pin their exact optional versions. Tests must cover relocated absolute links, source edits without manifest edits, dependency changes and cycles/aliasing, alongside existing platform neutrality and sealed producer/consumer folding tests.

Registry payload policy remains the existing exact lockfile/manifest identity; generated platform binaries inside an ungated wrapper are deliberately not hashed as portable source. Editable source is identified from host `packages/*` manifests and explicit `file:`, `link:` or `workspace:` dependencies (plus private source packages); its actual selected implementation is hashed even if the selected target is outside the host tree or copied rather than symlinked. Node resolution edges are discovered from each physical owner, including pnpm sibling realms; sharing/cycles are represented by deterministic graph node IDs. First-party source hashes are coalesced with the existing local-package fold during one capture, never cached across mutable captures. Identity name ordering uses JavaScript lexical order, never host locale collation.
