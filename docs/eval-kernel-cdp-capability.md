# Confined Eval CDP socket capability

The common handshake is `packages/rpc/src/protocol/cdpSocket.ts`. It requires an explicit native platform and never discovers network authority in its SDK realm. Base callers normally pass their own realm. Private Eval factories cannot do that: `EvalDO.ensureRuntimeSupport` loads them through the confined library loader.

`EvalDO.createActiveRuntimeRpc` records successful `workerdInspector.getEndpoint` and `panelCdp.getCdpEndpoint` replies per execution. Its injected binder accepts only that execution's exact URL/token, opens once, checks ownership on sends/events, and closes registered sockets in existing resident-session cleanup. Both workers and panel runtime factories receive this same binder. Raw fetch is no longer endowed when loading the CDP module.

The socket facade is frozen and has no prototype. Events are plain records; target/currentTarget point at that facade, not the native socket. Cancellation suppresses message delivery but permits terminal notifications while the execution is active, settling pending commands. Completion revokes every callback. Closing removes listeners and abort cleanup registrations.

The kernel regression bundles actual Base runtime factories, createCdpAutomation, BrowserImpl and CdpConnection into a private VM without fetch/WebSocket, then connects through the real kernel binder to a local CDP protocol server. It reproduces the old assembly failure, checks substitution/duplicate denial and actual panel acquisition, cancellation and completion. This proves assembly under the test environment; actual managed workerd CPU-profile smoke remains necessary and its earlier failed probes provide no timing measurements.

Native event dispatch does not assume caller AsyncLocalStorage propagation. The kernel re-enters only the captured live owner before delivering a sanitized protocol event, then the regular ownership/cancellation guard applies. Acquisition and sends retain their exact-current-owner checks. The regression explicitly dispatches a native message outside all Eval async context and checks successful owned delivery plus wrong-owner acquisition rejection. The first actual successor established an inspector TCP socket but did not produce profile evidence; that attempt is retained as an unresolved callback-progress failure, not a valid timing measurement.

The actual v4 probe reached native event delivery and failed strict CDP framing. A fresh real-workerd wire probe retained `{"id":1,"method":"Profiler.enable","params":{}}` as its acknowledgement. Upstream [workerd dispatchProtocolMessage](https://github.com/cloudflare/workerd/blob/main/src/workerd/io/worker.c%2B%2B) handles profiler enable/start/interval and heap snapshot itself, then serializes the command without initializing an empty result. `WorkerdInspectorProtocol` normalizes only these documented empty acknowledgements, bound to the exact outstanding command ID/method/parameters, within the existing workerd bridge. Standard results/errors pass unchanged; mismatches, duplicates, unsolicited frames and missing stop-profile results remain unmodified for strict client rejection. Pending state is bounded and retired with its bridge session.

A production bridge integration test launches the actual installed workerd executable, obtains its real inspector target, redeems an actual bridge grant, and connects the strict real Base CdpConnection. Profiler enable/interval/start and stop complete; the returned native CPU profile has real nodes and samples. It performs synthetic worker work solely to prove this protocol mechanism; it does not claim timings for the campaign's native contract probe or joint codebase. Nineteen kernel/bridge tests pass, including forged acknowledgement negatives.
