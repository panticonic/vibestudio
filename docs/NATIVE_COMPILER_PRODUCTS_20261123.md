# Isolated, shared Natlang frontend products

Inventory: `packages/builtin/src/eval-engine/EvalDO.ts` owns each confined SDK, realm and services. Base's `packages/natlang/src/programs.ts` formerly ran the entire virtual-project frontend synchronously in that shared Workerd event loop and cached executable values only within one Eval owner. Core's `runtime/virtual-project.ts` is used by Node, browser and Workerd; it now separates a serializable compiler product from fresh runtime instantiation. Model-serving engines do not run this frontend (engine inventory: Natlang `docs/ENGINE_PARITY.md`).

Existing host compiler workers execute trusted host transforms, and cannot safely execute a workspace compiler. BuildV2 already owns immutable source-bound library executables; `nativeWorkspaceRuntime.runJob` already owns their sandboxed native process execution. The new path reuses both mechanisms, without executing workspace code in the host realm or granting network/host access.

`build.compileProduct` first looks up the already-loaded SDK's exact execution digest/build key and checks its artifact digest. It compiles that provider's `/compiler` export at the stored immutable source state, with all workspace dependencies bundled. It never selects current HEAD. The sandbox compiles only explicit source/options JSON and writes a bounded private JSON result. The host joins that native job before reading it, refuses symlinks, bounds reads to32MiB, then removes its scratch directory on success or failure. Existing sandbox ownership joins/kills processes at workspace retirement.

A single NativeCompilerProducts instance belongs to each native workspace lifetime. It serializes cold jobs, coalesces equal requests, and caches at most32 products/64MiB, keyed by exact compiler bundle+format and all frontend input JSON. Each caller receives a separate JSON parse. Shared jobs have no Eval cancellation signal: cancelling one request cannot abort another owner borrowing the same pure job. Model/runtime/service/module instances never enter this cache. Base verifies returned source identity and instantiates modules/realms separately, preserving authored TypeScript root/native-service tracing.

Defaults: offload and shared cache enabled. `VIBESTUDIO_OFFLOAD_NATLANG_COMPILER=0` restores local frontend compilation; `VIBESTUDIO_CACHE_COMPILER_PRODUCTS=0` keeps offload but disables shared products/inflight coalescing. Structured `native.compiler-product/1` logs expose digest-only hit/join/miss/completion, queue time, compile time and product bytes. No source text, credentials or model values are logged. Provider ABI4 requires the matching Base provider and Host deployment together.

## Compiler child heap

The pure frontend receives the complete linked project, including for a TypeScript entry. It is not entry-pruned. Native workspace children deliberately do not inherit the host's V8 arguments or `NODE_OPTIONS`. Compiler jobs therefore pass `--max-old-space-size=3072` explicitly, independently of ordinary native jobs. `VIBESTUDIO_COMPILER_HEAP_MIB` accepts64–8192MiB, or0 to restore the Node default. This is a heap ceiling rather than a reservation; the enclosing ledger/cgroup still bounds all workers together. Shared serial frontend admission and immutable product reuse reduce concurrent compiler demand but do not substitute for sufficient cold-compile capacity.

Mechanism inventory: `packages/natlang/src/programs.ts` in Base supplies the full project to the pure compiler; `EvalDO` delegates captured compilation through `build.compileProduct`; `src/server/services/buildService.ts` binds the immutable SDK provider; `nativeCompilerProducts.ts` serializes/cache-coalesces work per workspace; `nativeWorkspaceRuntime.ts` launches that work with the explicit compiler-only flags. `packages/process-adapter/src/isolation/workspace.ts` defaults all other commands to empty `execArgv`, and `workspaceChild.ts` deliberately avoids parent flag inheritance. The V8 option is passed through that existing cross-platform launcher, not through a sandbox environment exception. Managed llama, wllama, Python/SGLang model serving do not implement this Vibe native frontend launch; they use their own model engines. Direct standalone Natlang Node compilation uses its caller's Node capacity; Workerd receives the serialized compiler product and instantiates a separate owner runtime. The change does not increase Workerd isolate limits or ordinary workspace command limits.
