## Versioned read recovery inventory and policy

Both `createWorkspaceSemanticPort` and `createWorkspaceSourceProviderV1` now use one shared typed transport adapter consumed by `WorkspaceVcs`, FS program/source reads, graph/build source reads, and semantic reference authorization. Canonical `vcsMethods` already declares operation class and reference paths. Reads with validated immutable state-node references can repeat the exact selectors without authoring any change. `workspaceSourceTemplateInstallation(eventId)` is a pure exact-event bootstrap read; `vcsReferencesReachable` and `vcsIsStateDescendant` are pure exact-reference checks; their receiver evaluates current context reachability/authority on every dispatch. `readFile`/`readFiles` return exact hash-bound host-read descriptors; ordinary blob reads do not issue semantic effect acknowledgements. Writes, content/effect acknowledgements, context lifecycle, initialization, and dynamic-head reads are not replayed. Existing generic `DODispatch` remains exactly-once and still resolves active receiver/executable authority for each attempt. The outer admitted service retains its original lifecycle/authority scope; recovery grants no new capability.

The adapter now snapshots receiver identity and the complete validated request before the first attempt. It makes at most two dispatches, only for structured dispatch ambiguity with an actual reset/closed/refused-connection cause. Unknown errors, semantic codes, protocol/authorization failures, owner cancellation, and compound failures propagate immediately. Every failed transport attempt logs its full failure graph, method, receiver, immutable request digest and retry disposition. Exhaustion preserves both original failures and their causes. There is no timer, delayed retry, mutable-selector fallback, write retry, or model retry. `VIBESTUDIO_RETRY_PINNED_READS=0` disables this recovery for diagnosis.
