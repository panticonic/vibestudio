# Native TypeScript compiler memory

TypeScript 7.0.2 runs a native Go executable, both through its CLI and its synchronous API. Node heap limits do not set the Go collector limit. The installed API synchronously spawns its child with the parent environment (`typescript/dist/api/syncChannel.js:99,126`); its close method kills that owned child. The CLI replaces its Node wrapper with the native executable (`typescript/lib/tsc.js`).

Inventory: scripts/infrastructure-package-cache.mjs, scripts/lib/host-validation.ts, scripts/build-website-runtime.ts and packages/typecheck/src/service.ts are all synchronous API creators. scripts/lib/validation-projects.ts and the infrastructure build emitter launch the compiler CLI; userland checks use ValidationProjects. The other TypeScript unstable imports are AST-only or consume the already-owned compiler snapshot. Natlang's standalone ts-host uses JavaScript TypeScript 5.9.3 (ts-host/package.json:46 and ts-host/src/scope-compiler.ts:395 in the Natlang repository); it does not spawn this Go compiler.

Use one standard Go soft collector limit across these native compiler entry points, preserving an explicitly supplied GOMEMLIMIT (including off). This changes collection policy, not compiler options, project scope, diagnostics, or language semantics. It does not replace an operation's cgroup budget or its aggregate admission. Independent custom infrastructure builds must also honor the existing VIBESTUDIO_MAX_CONCURRENT_BUILDS budget rather than silently using pnpm's unrelated default concurrency.

Baseline: the integrated Host transitive check was killed in 1.5, 2 and 4 GiB cgroups, most recently at 4 GiB after 73.95 seconds with no diagnostics. These are incomplete checks, not passes. Verify the complete check after applying the native policy; collect bounded process-tree RSS outside its cgroup, without changing the declared cap or overlapping a separate memory experiment. No latency improvement is claimed from the baseline failures.

Validation in the private Host checkout: all 27 native API/infrastructure tests passed (607 MiB cgroup peak); the three policy tests and two original-project native CLI validation tests passed (105 MiB peak). Release lifecycle tests initially could not import this cold checkout's unbuilt RPC package; they remain outstanding until normal infrastructure production completes. The complete transitive Host check is queued at the unchanged 4 GiB cgroup cap, Node heap 3072 MiB, and operation concurrency one. A bounded observer outside the group records whole-tree compiler identities, RSS and inherited GOMEMLIMIT. A queued, killed or diagnostic-free incomplete run is not a pass.

The four API owners and the CLI children of their build/validation operations share this policy. Direct, unmanaged package `tsc`/watch invocations have no Host API lifecycle and retain the caller's ordinary Go environment; this change does not claim to intercept arbitrary compiler executable invocations. Explicit GOMEMLIMIT, including off, remains the standard opt-out.
