Imported Eval libraries have private globals and intentionally cannot reach ambient `fetch` or `WebSocket`. The CDP client must receive an endpoint-bound socket capability from the native runtime after its own approval-gated endpoint lookup. Base's `packages/cdp-client/src/socket.ts` shares the existing handshake; `packages/runtime/src/shared/cdpSocket.ts` captures the native platform and refuses URL/token substitutions. Official testkit profiling and panel-mediated CDP both consume that capability. Confinement is unchanged.

A second boundary gap existed in Host: `authorizeInternalRequest` accepted only panel `/cdp/` grants, while `WorkerdInspectorBridge` correctly minted a separate private inspector grant for `/workerd-inspector/`. Worker fetch upgrades therefore could not reach the approved loopback inspector, even after the transport became available. `inspectionEgress.ts` now routes both exact gateway paths to their separate authoritative grant validators. It allows only GET, exact gateway origin and one nonempty token; malformed paths, different targets, different origins, ambiguous grants, token substitutions and cross-bridge tokens fail. Validation does not consume the short-lived grant; the authenticated WebSocket bridge redeems it once. The live inspector bridge is installed/cleared with its managed lifecycle, so a stopped inspector provides no transport authorization.

Tests exercise both bridge namespaces, exact decoded targets, stopped-grant invalidation and denial cases. The existing bridge/service tests continue to exercise ownership/permission and pre-ready native socket lifecycle. Base's regression bundles the actual CDP connection/browser and official profiler into a VM without network globals and exchanges real WebSocket protocol messages through the bound native capability. That regression does not claim a live CPU measurement: the actual managed Eval profile smoke is a separate step after building these source refs.
